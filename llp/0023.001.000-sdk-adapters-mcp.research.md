[observed] `packages/core/src/port.ts`, `docs/product-integration.md`: the SDK is the recommended application path.

## Storage and product behavior

[observed] The public `Store` contract now includes bounded listing, full erasure and a revision token. An atomic
conditional write rejects a stale revision with `ConflictError`. Extraction, saves/corrections, forgetting and
folding use conditional commits. Recall checks the persisted token when it completes; deletion by a separate
engine cannot leave its in-flight response containing forgotten evidence. The host retries conflicts with stable
IDs, preferably through a per-person durable queue. Model calls are never inside adapter transactions.

- SQLite: existing transactional schema plus origin/save metadata and revisions. Bun and Node adapters share the
  implementation. A revision change invalidates cached vectors across store instances.
- PostgreSQL: application-owned `pg` pool; isolated JSONB table/index; native transactions and conditional writes.
- Firestore Node: application-owned server client; per-person records and revision guard in a native transaction.
- Firestore REST: fetch-only entry point for Workers, host-supplied OAuth tokens, the same record layout, and an
  atomic commit with an update-time precondition. No Node or gRPC runtime dependency on this path.

[observed] `packages/core/src/save.ts`, `inspect.ts`, `memory.ts`: explicit saves preserve the exact fact, create
explicit provenance, return only after commit, and retry by a stable caller ID. Corrections retain history and
invalidate the dossier. Automatic extraction cannot supersede a pinned group. Source-based forgetting leaves
processing tombstones so delayed deliveries cannot restore erased input. Paginated inspection and evidence lookup
supply a memory viewer's backend surface; no viewer UI or BetterMind memory migration was implemented.

[observed] `packages/core/src/split.ts`, `extract.ts`, `test/coverage.test.ts`: extraction no longer clips each
message/window to a prefix. Ordinary messages remain whole; oversized messages are split with complete Unicode
coverage and common source IDs. All derivations of a turn commit together, and selecting one chunk for forgetting
removes all chunks of the same human source. Regression cases cover facts after 4,000 and 12,000 characters and a
late-chunk failure/retry. Historical Python also clipped input; this is a coverage improvement, not evidence that
only the TypeScript port introduced that behavior.

## MCP

[observed] `packages/mcp/`: official TypeScript MCP SDK v2, negotiated modern and legacy transports, tools with
schemas/structured results/annotations, resources, usage prompt, stdio executable and authenticated HTTP handler.
The host resolves identity and capabilities for every HTTP request. Tools cannot choose a person. Read-only is the
default; writes and forgetting are separately enabled. Unknown/provider errors do not echo conversation text.
Tool deadlines propagate through the SDK, results are bounded, and stdout is reserved for MCP traffic.

Actual clients exercised HTTP and stdio, concurrent person isolation, strict inputs, exact save retries, correction
history, deletion, deadlines and persistence across stdio reconnects through the Worker API/SQLite host. The ten
read-only questions in `packages/mcp/evals/questions.xml` have expected values verified using MCP pagination and
evidence calls on invented records. No answering LLM was run; this is not a measured agent tool-use success rate.

Node Firestore conformance stalled under Bun's gRPC behavior here and passed under Node. Its tests therefore run

that Workers rejects fetch `redirect: "error"`; the client/REST adapter now use manual redirects and reject 3xx
responses explicitly, preserving credential protection on both runtimes.

## Remaining limits

[inferred] Ready for product integration and staging evaluation, not an automatic production replacement. The host
still owns authorization, token acquisition, background jobs, usage budgets and migration/shadow evaluation.
Exact vector search is linear per person. Firestore listing bounds returned rows, not underlying document reads,
and atomic writes/erasure remain subject to native size limits. MCP cannot force the host model to call recall.
Full end-to-end model quality, large-history cost/latency and production traffic have not been established here.
