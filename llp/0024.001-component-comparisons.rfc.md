# LLP 0024.001: Comparing SDK components

**Type:** RFC
**Status:** Draft
**Systems:** Evaluation, Core, Research, Interfaces
**Author:** Adam Zvada / Codex
**Date:** 2026-09-28
**Related:** LLP 0024, LLP 0023.001, LLP 0015, LLP 0020, LLP 0022

## Purpose

[confirmed] (Adam Zvada, 2026-09-28): know the actual TypeScript scores, compare implementations fairly, and make
models, routers and Jev interchangeable building blocks that are easy to verify through the SDK.

## Component boundary

[inferred] Keep `LanguageModel`, `Embedder`, `Decider` and `Store`. Add a small `Picker` port for choosing among
already retrieved candidates. Built-ins adapt the model ranker, closed-question decider and unchanged vector order;
a router can choose a picker by statement/window kind. Keep both searches in the default conversation path.
Separate model overrides for extraction, linking, dossier and ranking, and a detector decider override, avoid
changing every stage when testing one. Defaults must preserve existing prompts and behavior. Validate selected IDs
against the supplied candidates; a custom picker cannot inject another person's records. Check every configured
provider against allowed processors before calls.

## Portable evaluation

[inferred] Ship `@fluiddb/eval` with the existing validated ordered dataset and grader. Products pass their SDK
dependencies and a fresh store; comparisons use a factory per variant and always close owned stores. Fixed dataset
keep limits and deterministic IDs/clock make provider requests reusable. Freeze the input once; each variant gets
a validated copy. Gold enters grading only after recall. Retain per-metric numerators/denominators, failure IDs,
repetition precision/recall, latency, component IDs and paired check improvements/regressions. An interrupted
variant is an error, never a passing score over the surviving subset. Do not turn a mixed basket of checks into a
general accuracy claim. The grader measures source-window retrieval and explicit regression criteria, not answers
from a therapist or clinical benefit.

## Experiment declared before calls

- **H1:** Default components preserve all 50 checks on the frozen 15-probe synthetic fixture. A deliberately broken
  picker produces detected regressions; swapping providers does not leak labels or share memory across variants.
- **H2:** On that same fictional fixture, compare real OpenAI extraction/embedding/linking/dossier with vector-order,
  OpenAI model ranking, OpenAI closed-question picking, Jev picking/detection, and a per-kind routed picker.
  Report every metric, false-positive/false-negative counts and failures. No minimum quality threshold is asserted:
  this is a small diagnostic comparison, not proof of superiority or a replacement for the 392-question research.
- **H3:** Every comparison uses one shared **$3 total cap** (including failed/parallel calls), exact request caches,
  single network attempts, and zero-network replay. Prices are verified from primary provider sources before use.
  Cached latency and incremental billed estimates are labelled separately from production latency/full-run cost.

Only the tracked fictional fixture may be sent to Jev/OpenRouter/TypeSafe. Its dataset must explicitly declare
`synthetic: true`; default/custom/private inputs remain OpenAI-only in the CLI. The original 18-account corpus
continues to use its cache-only replay; historical scores are displayed with their Python provenance.

## Verification

Meaningful tests cover processor enforcement on overrides, picker foreign/duplicate IDs, stage dispatch, shared
budget across provider endpoints, deterministic replay, missing variants and paired comparison failures. Run the
existing core/workspace/runtime/package checks. Record fresh real-model results and actual cache/spend coverage in
a child Research document and the findings ledger. No automatic promotion of a new default from this small run.
