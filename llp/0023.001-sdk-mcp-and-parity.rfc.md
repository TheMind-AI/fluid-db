## Purpose

[confirmed] (Adam Zvada, 2026-09-27): reproduce the research results in TypeScript and prepare a clean SDK and a
high-quality MCP server for product integration. The research remains the design basis; product requirements do
not require reproducing BetterMind's internal profile/episode schema.

## Research protocol

Declare these before the comparison. Provider responses are cached; private data remains outside tracked paths,
other people's data uses OpenAI only, and logs/reports expose aggregates rather than conversation text.

- **H1: retrieval parity.** On the original frozen questions and stored research memory, the TypeScript SQLite
  retrieval/picker path matches the corresponding Python configuration's selected evidence and its provenance
  grader. Report exact set agreement, window and statement hits, configuration and any unavailable cases. Cached
  provider decisions are allowed only for equivalent inputs, never substituted by labelled answers.
- **H2: end-to-end quality.** When the original input/provider/grader responses can be replayed, compare the
  TypeScript pipeline on the same cohort and grader with the corresponding research result. Report extraction,
  retrieval, answer and grading coverage separately. A read-path parity run alone does not establish this hypothesis.
  A fresh model run or changed input scope is a new comparison, not an exact reproduction of the old score.
- **H3: complete input.** Synthetic regressions demonstrate that a fact after character 4,000 and a fact beyond a
  multi-message 12,000-character window reach extraction, retain source provenance and survive recall. Failure
  during processing leaves all source turns retryable. Historical parity uses historical input; expanded input is
  tested separately so fixing truncation cannot quietly redefine the benchmark.
- **H4: product interfaces.** Protocol-level MCP tests and packaged Node/Worker consumers pass, including identity
  isolation, malformed input, cancellation, permission checks, durable receipts and source-based forgetting.

Re-analysis is cache-only with zero new provider requests. If missing responses require a new run, reserve costs
before sending with the existing TypeScript transport and a **$3 total round cap**, current explicit prices,
single-attempt requests and persisted usage. Do not silently fall back to fakes. Missing datasets or caches are
reported as missing coverage, never as passing quality. Results belong in a child Research document and LLP 0002.

## SDK boundary

[confirmed] (Adam Zvada, 2026-09-28): distribute one public package (LLP 0023#packaging). Schema, core, provider and
storage modules remain private implementation boundaries; the earlier proposal for separate public packages is
superseded.

[inferred] Offer a small person-bound SDK surface for
product callers and transport adapters: ingestion, recall with a rendered prompt, dossier, explicit memory saves,
inspection, forgetting and operational status where supported. Bind the person outside agent-controlled inputs.
Use validated inputs/outputs, stable IDs, AbortSignal/deadlines and typed failures. HTTP acceptance and completed
processing are distinct; a save receipt is returned only after persistence.

An explicit save stores exactly the requested fact without relying on model extraction. Corrections preserve
provenance and validate the referenced record in the same person's memory. They must not fabricate conversational
turns or claim an inferred fact was spoken. Existing automatic extraction stays the researched path. Inspection
uses bounded pages and source links, not arbitrary SQL or dumping a person's entire history.

[observed] `Api.Remember` now accepts `pinned` and `origin` (`explicit`, `agent`, `import`). Defaults remain
pinned/explicit for existing consumers. Hosts can preserve unpinned proactive and imported records without
claiming that the person spoke a fabricated turn or explicitly requested a save. Retry identity includes both
fields; changing them needs a new save ID. The source window labels its actual origin. This closes the save-intent
gap found during BetterMind integration, while account policy and migration metadata stay in the product.

[observed] `previewForget` uses the same transitive source-window closure as `forget`, returns the current
person revision and performs no writes/model calls. Passing that revision into `forget` rejects changed scope,
including concurrent writes and erasure. Session deletion also tombstones raw session input that has no derived
window yet; a preview lists derived rows, not a host's pending queue. Product consent remains host policy.
`source({ window, offset, limit })` returns bounded Unicode-code-point pages, with `nextOffset` for complete
source access. Both APIs exist on the SDK, HTTP client/Worker and MCP. Imported/agent/explicit saves use their
actual origin in evidence text; only conversational statements can trigger retelling detection.

## Bounded save batches

[observed] `Person.rememberMany` accepts one to twenty independent facts with distinct stable save IDs.
It preserves each fact's session, date, pinning and origin, embeds only new facts in one embedder invocation, and
commits their records, vectors and processed-ID tombstones in one revision-guarded write. The same call is
available through the HTTP client and Worker. Corrections use the existing single-save `remember` API.
Duplicate/new mixed retries are supported; changed content or a forgotten ID rejects the entire batch before
embedding or persistence. Cancellation, provider failure and a concurrent memory revision leave no partial batch.
Provider adapters may split that invocation into bounded HTTP requests: twenty short facts produce forty
embedding inputs and currently use two concurrent OpenAI requests.

The `Changes.turns` port accepts either its existing single-session object or a list of those objects, so a batch
retains each original session's processed IDs. Built-in adapters accept both. Custom Store implementations must
handle the list form before exposing batch saves. Backend migration cursors advance only after this batch commits.
This bounds transport work per import page without weakening complete-import, erasure or account ownership rules.

## Database adapters

[confirmed] (Adam Zvada, 2026-09-27): the therapist backend integrates through the SDK and chooses its database.
Implement PostgreSQL, local SQLite and Firestore first; leave MongoDB to a later adapter of the same contract.

[inferred] Keep the existing domain `Store` port as the public abstraction. It names original turns, processing
IDs, windows, statements, groups, dossier, atomic changes and person-scoped vector search. It does not expose SQL,
Firestore references, model calls, permissions or MCP. Native adapters may share the pure write-planning code that
preserves raw-log immutability, folded-window state and tombstones; that helper is not a second public database API.
Each adapter implements the same conformance suite. Database connections and credentials are provided by the host,
which also owns migration timing and connection shutdown. SDK access is server-side only.

For initial PostgreSQL/Firestore adapters, exact vector search stays in the transaction's database alongside source
records, scoped to one person. No second vector service or eventually consistent deletion is introduced. This is
linear at personal-history scale, not an ANN performance claim. Database-native limits must fail atomically rather
than split one logical write into partially committed batches. Conditional writes validate a person revision inside the atomic commit. Stale derivations fail with a conflict
and keep source IDs retryable. Read completion checks the persisted revision, so another process cannot cause
in-flight recall to return forgotten evidence. The host queue retries conflicts; model calls never hold a database
transaction. The Worker additionally coordinates one Durable Object per person.

[observed] The target backend uses Cloudflare Workers and a custom Firestore REST client. Provide a fetch-only
Firestore entry point with host-supplied OAuth access tokens in addition to the Node client adapter. Both use the
same record layout and revision guard; REST uses atomic commit with an update-time precondition.

## Complete input

[inferred] Replace prefix clipping with bounded contiguous windows/chunks. Retain whole ordinary messages and split
oversized messages with source IDs preserved. A turn is marked processed only when its entire derivation commits.
No extractor-side slice may silently discard a window tail. Keep budgets explicit; changing input coverage is
documented separately from reproducing historical results.

[observed] Turns accept up to 200,000 UTF-16 characters, covering the product's 32-by-4,000-character multipart
message limit. The existing 12,000-character splitter preserves every part with the same source ID, so forgetting
one part removes the complete source. Long composed product IDs are deterministically bounded by the adapter.

## MCP

[observed] The single FluidDB package's `/mcp` and `/mcp/http` entry points use the official TypeScript SDK. The
private `packages/mcp` module keeps MCP imports out of the engine's dependency graph. Local integrations use
stdio; products can mount a Web-standard Streamable HTTP handler. Both share the same tool definitions and SDK
adapter. Importing the package root does not import MCP, Node or HTTP frameworks.

- Tools expose recall, ingestion, explicit save, bounded inspection, dossier/status and forgetting where permitted.
- Descriptions explain when to call them, what the result means, and source-window deletion's scope. Results are
  structured and bounded, with readable text and source IDs. Errors are actionable without leaking provider text.
- Identity and allowed mutations come from server configuration/authentication, never from a tool's person ID.
  HTTP authorization runs for every request; Origin/Host checks protect local servers. No unauthenticated remote
  default and no deployment-wide token passed through to end users.
- Read-only mode omits mutation tools. Forgetting is separately enabled. Tools have accurate annotations, but
  permissions are enforced in code. Account-wide erase remains a host lifecycle operation.
- A resource/prompt teaches the researched turn workflow: keep the dossier current, retrieve at a turn, and use
  supported memories explicitly. Memory text is untrusted evidence, never instructions. MCP alone cannot force
  the host model to use a tool, so the SDK integration guide also shows the automatic per-turn path.
- The stdio executable writes only MCP messages to stdout and shuts down cleanly. Packaged artifacts include the
  executable, declarations and configuration examples; installation never publishes or deploys anything.

Use the current [official SDK](https://github.com/modelcontextprotocol/typescript-sdk) and
[transport specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports).
