live mutations wait for a complete authoritative run. This data copy is not a second active engine.

## SDK seams

[observed] `packages/core/src/forget.ts` supplies the shared transitive source closure for preview and deletion.
`previewForget` returns a revision; `forget` checks it before selection and inside the final atomic commit. The
host owns consent and additional aggregate-summary invalidation. Session deletion includes raw input, even before
extraction has produced records. `source` provides bounded Unicode-code-point pages without prefix-only evidence.
Both operations are exposed through the person-bound SDK, typed HTTP client/Worker and MCP.

[observed] Imported and agent-saved facts retain truthful evidence wording. Retelling uses only conversational
statements and counts/dates only conversational group members; imports cannot manufacture earlier disclosures.
The existing complete splitter accepts 200,000-character turns, covering the host's multipart bound.

## Product review and fixes

[observed] Synthetic regressions in BetterMind `test/fluiddb-memory.test.ts` and `test/fluiddb-runtime.test.ts`
cover pending/raw conversation forgetting, selecting details omitted by extraction, shared-source previews,
person filters, explicit pin promotion, full source continuation, long accepted messages/IDs and actual source
message links. The adapter retains its account-erasure transaction and revision/source-generation guards.
The initial cutover's feedback sanitizer read FluidDB facts and failed closed without redaction evidence.
The 2026-09-29 product feedback design in LLP 0023.005#technical-feedback-routing replaces that behavior:
validated technical reports are preserved without reading memory or automatically collecting user context.

[observed] Text turns retrieve memory before responding, with cancellation, deadline and a revision fence.
Voice uses FluidDB startup context/tools; XO 0.3.0 lacks a portable before-turn retrieval hook, so automatic
per-turn voice retrieval is not claimed. The local simulator, XO CLI and ordinary evaluations use FluidDB;
historical evaluation requires an explicit engine choice. Simulator saves/forgetting use its fictional clock.
Missing imported memory is not mistaken for a first meeting. Source-reading chat receipts store IDs/offsets,
not another copy of source content.

## Native iOS smoke test

Follow-up: LLP 0024.002.000 records restored provider readiness after replenishing credits, a 30-message live
product-simulator memory test, complete paged legacy-context import and native loading retry handling. The
original intermittent voice-to-text trigger remains unconfirmed; these checks do not certify a production launch.

[observed] On 2026-09-28, the BetterMind `roseau` app ran in an iPhone simulator against the actual local
backend, the published `1.0.0-next.3` package, isolated Firestore and live OpenAI. Synthetic text memory was saved,
recalled in a different conversation, forgotten through the tool, and absent from two explicit recall calls in a
third conversation. A generated speech fixture also produced a real Realtime transcript, successful memory-save
receipt and pinned FluidDB statement. These are individual functional checks, not an accuracy comparison.

[observed] The same app run exposed issues outside the verified memory operation: voice-to-text once remained on
loading placeholders despite persisted messages (reopening showed the transcript); two later voice starts failed
before provider readiness; a subsequent text stream returned `agent.error` and the client silently cleared its
draft. The iOS network stream now fails on `agent.error`, retaining the draft through its existing error path.
Replaying that exact SSE failure through a loopback fixture verified the error label and restored input. The
app build and 47 existing Swift tests passed. The loading and provider-startup causes remain unresolved. One
model greeting also identified itself as ChatGPT despite the Mind persona instruction.

[observed] Evidence is in `.context/ios-fluiddb-smoke/report.md` and its screenshots; backend receipts are in
`.context/fluid-ios/`. No production account, migration, deployment or real personal conversation was involved.

outside this smoke test. This is not a complete app launch sign-off.
