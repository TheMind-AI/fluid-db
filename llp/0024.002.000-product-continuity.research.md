## Scope and evidence

[observed] This run used BetterMind's published `@fluiddb/fluiddb@1.0.0-next.3`, actual product memory tools and checkpoint/context code, and authored fictional inputs. Live conversation generation used OpenAI Chat Completions through the product simulator's OpenAI-shaped transport; memory used real GPT-5.6 Luna and text-embedding-3-small. The simulator store was `JsonFirestore`. Real Firestore transaction and migration behavior was checked separately against the disposable emulator. This is not a continuous native voice test or a comparison with the old memory engine.

Detailed evidence is ignored: backend `.context/fluid-followup/` contains `live.ts`, its bundle, raw response cache, `live-results.json`, `live-state.json`, `probes.ts`, `probes-results.json`, budget ledger and check logs. SDK `.context/ios-fluiddb-smoke/` retains native recovery evidence and the earlier smoke report. XO uses its maintained `.xo/verify/` evidence directories.

## Findings

- **Import:** H1 passes the bounded regressions. The previous importer reused prompt-sized lists: 100 flat notes, 20 topics, five episodes and ten old session summaries; a profile also suppressed old flat/topic notes. The backend now pages each complete eligible collection, including continuation inside long documents. A 155-record mixed fixture and a 105-note real Firestore fixture pass. Forget boundaries still exclude unversioned old summaries/notes, and old records remain unchanged.
- **Longer conversation:** 15 live user/assistant exchanges (30 messages) completed, including automatic extraction on every turn. The model selected `recall_memory` for an imported sketchbook fact and `remember_memory` for a new favorite-trail fact. Direct tool probes in a fresh conversation recovered the trail, returned its source reference, and `read_memory` returned the matching evidence. H2's originally declared 20 intervening user turns was **not reached**: generation was stopped to preserve the conservative $2 reservation cap. No 20-turn pass is claimed.
- **Correction:** a live correction returned `stored: true` and superseded the earlier group. The initial probe incorrectly counted superseded historical records as active; that assertion is invalid. A free regression explicitly checks that correcting one member supersedes all three wordings while preserving history. Earlier probe mistakes (an array passed to the scalar `replaces` field and reading the first unrelated excerpt) are preserved in `probes-invalid-test-input.json`, not counted as engine defects.
- **Forget:** deleting the selected trail sources completed, and a new conversation's semantic recall did not return either trail name. The active store also contained neither name. Imported aggregate summaries were invalidated by the existing product policy. Historical chat messages are not themselves erased by a fact-level forget.
- **XO startup:** a maintained `cli-provider-readiness` recipe reproduced the explicit OpenAI “no credits remaining” response before any model turn or memory tool. With credits restored, the same recipe reached readiness and closed cleanly with no usage. The ten free lifecycle/tool recipes also passed. No XO runtime defect was established.
- **Native loading:** the app could silently decode a chat as nil and still leave the placeholder view visible. The native fix propagates decoding errors, treats missing metadata/message failures as a retryable loading error, preserves the chat ID and draft, and disables sending until load completes. A normal local attempt also showed the placeholder behavior; its precise original failure trigger remains unconfirmed. On the final build, a synthetic chat with an invalid timestamp showed the error state; repairing it and retrying recovered all three transcript messages without restarting. The first automated retry tap left the error visible; the second recovered it. This establishes recovery, not a first-tap timing guarantee. Screenshots are SDK `.context/ios-fluiddb-smoke/11-load-error.png` and `12-load-recovered.png`; the local fixture is `chat-load-fault.mjs` in the same directory.

## Cost and latency

[observed] The shared, persisted ledger reserved **$1.960443 of the $2 cap** across failed starts, the long run and the targeted probes. Recorded successful usage was **$0.152674 at conservative rates**, not a final provider invoice. Cancelled/ambiguous requests retain their reservation; their actual bill is not inferred. Requests and raw responses remain cached locally; no private data was used.

Two initial conversation requests were rejected because GPT-5.6 Luna's Chat Completions function tools do not accept low reasoning effort. The simulator test selected `none` for the conversational tool caller; memory extraction/ranking retained `low`. This adjustment affects the test adapter, not the product's Realtime provider.

[observed] Median full simulator turn time was 20.6 seconds, maximum 34.1 seconds. This includes context retrieval, agent/tool work and the synchronous simulator checkpoint; it is **not** native time to first token. A direct uncached semantic recall took about 9.4 seconds; source reading took milliseconds. Automatic retrieval sometimes exceeded the product's context deadline. These samples justify further latency measurement, not a general latency estimate: the host was severely overloaded (load average above 500 and roughly 15 GB swap during verification).

## Verification and deployment limits

[observed] Backend lint, types, bundle and 525 API tests passed; 11 Firestore emulator checks passed. The final memory regression file passes 24 tests, including one additional correction/history assertion added after the full suite. The final native recovery build and 47 existing Swift tests passed. XO lint/types/build passed; its broad test run had four timeouts under host contention, and all 64 tests in the affected files passed when rerun with one worker. Its packed artifact passed 11 integration scenarios plus runtime/types/Workers checks.

Completed preview FluidDB imports are deliberately not rebuilt automatically. If such an import omitted older records, it needs a separately reviewed backfill; new and incomplete legacy imports use the complete paged path. No production migration, deployment, real Firebase authentication, physical-device audio test or old-versus-new quality comparison occurred. The historical research score is not re-established by this run.
