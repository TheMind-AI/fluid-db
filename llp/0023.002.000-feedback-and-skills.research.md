## Implemented surfaces

[observed] `packages/feedback/` implements a fetch-only SDK for explicit HiveNet reports. Its strict input
contains category, subject, structured failed task, bounded memory-case descriptors, thread/question IDs and an
idempotency key. It has no Store access, environment collection, outbox or automatic reporting. Responses retain
guidance, asks and known-issue state as data. Typed delivery errors retain retry identity without upstream text.

[observed] `packages/cli/` provides `fluiddb feedback` (flags or JSON file/stdin) and offline `fluiddb skills
list/read`. `packages/mcp/` independently enables reporting with `feedback: true` or `--feedback`, without enabling
memory writes or deletion. Instructions expose the alternate keyless HiveNet paths when the tool is disabled.

[observed] Canonical memory and feedback SKILL.md files in `packages/skills/skills/` generate a shared static
catalog. MCP supports the accepted Skills extension (`skills/list`, `skills/get`) and ordinary resources, plus
`fluiddb_read_skill`. All manifests carry complete frontmatter, digests and byte sizes. CLI and HTTP serve the same
bytes. The Worker exposes `/.well-known/agent-feedback.json`, `/llms.txt` with the requested agent block, and skill
markdown. AGENTS.md and its CLAUDE.md symlink contain feedback instructions. There is no separate docs website or
starter-template surface. Nothing was deployed; the routes become available with the next deployment.

## Verification

[observed] `bun run check`: 184 engineering tests pass, four opt-in live-provider tests remain skipped, and the
existing 15-probe/50-check deterministic replay passes with zero provider calls. Database conformance remains the
separate verified run documented in LLP 0023.001.000; no storage behavior changes in this increment.

[observed] Feedback tests validate submitted envelopes and example replies against the published HiveNet 0.6.0
schemas. Tests cover thread/question continuity, privacy boundaries, invalid input, safe ambiguous failures,
redirect rejection, oversized/invalid receipts and cancellation. CLI tests cover structured flags, JSON/stdin,
offline skill reading and executable exit/stream behavior. MCP tests use real clients over both legacy and modern
HTTP: resource digests, skills/get, fallback tools, malformed cursors/URIs, independent reporting permissions and
owner reply propagation. The modern wire response is checked for complete-result and public cache metadata.

[observed] Eleven tarballs install outside the workspace and work in plain Node and strict NodeNext TypeScript;
the feedback SDK, skills catalog, CLI executable and MCP skill tool are exercised. Actual workerd tests verify
public discovery and execute the feedback SDK with intercepted outbound delivery. Both SKILL.md files pass the
skill-creator validator. Generated-catalog drift, formatting and LLP reference checks pass.

## Limits

Free text is not automatically redacted; callers review what they send and use synthetic reproductions. Feedback
is an external support channel, not a source of trusted labels or personal memory. Owners curate reports into
reproducible evals. Attachments use HiveNet's explicit CLI, not the FluidDB SDK. Neither the therapist backend nor
its viewer is migrated by this increment. The full-model quality limits in LLP 0023.001.000 still apply.
